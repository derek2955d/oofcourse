# 网站管理助手（开发版）

位置：`/zh/admin/assistant` 或 `/en/admin/assistant`。必须已有真实管理员角色。普通用户无法生成、读取来源记录或保存助手草稿。

## 当前能力

粘贴公开活动资料及 HTTPS 来源网址 → AI 生成中英文标题、原创简介、日期和原文证据 → 人工核对并选实际地区 → 保存私有草稿 → 打开原有发布编辑器，补充有授权的图片并提交 → 管理员审核发布。

同一来源 URL + 活动最后一天只创建一个草稿；并发重复保存也返回原记录。来源原文和双语候选保存在仅管理员可读的 assistant_imports 中，公开商品/活动仍沿用现有单语言正文，不会凭空变成双语发布。记录不代表已发布；以内容审核页面状态为准。同一个 URL 的不同场次请分别核对日期；不同 URL 的相同活动仍需人工判断。

AI 结果必须有可在输入原文中找到的日期和地点摘录，过期日期不接受。摘录存在不保证模型理解正确，必须人工核对。AI 无工具权限，不能发布、修改账号、执行 SQL 或采用网页中嵌入的指令。每个管理员每天最多 10 次生成请求（失败也计入）和 20 次新草稿保存；这不是供应商美元消费上限。

## 尚未启用的能力

当前没有定时网页搜集、全网搜索、自动图片下载、自动发布或通用聊天执行功能。输入 URL 仅记录出处，不抓取该网页。此版本是有人审核的活动管理助手基础，并非已运行的全自动网站运营服务。现有过期清理接口 `/api/cron/expire` 仍需单独配置服务端凭证和调度器，不因本功能而自动启用。

## 启用前

1. 审查并在开发 Supabase 项目执行 `supabase/migrations/202610300011_website_assistant.sql`。这份独立迁移依赖已有 001–009 基础，不要求为助手启用投稿原型 010；不要重跑已执行的文件。
2. 由运营者确认 AI 供应商、模型和消费预算，再在 Vercel Preview 安全配置 `OPENAI_API_KEY`、`ASSISTANT_MODEL`，设 `ASSISTANT_ENABLED=true` 并重新部署。此代码调用 OpenAI Chat Completions，需支持 strict JSON schema 及 max_completion_tokens 的模型。没有默认模型或自动付费购买。
3. API key 只放服务器环境变量，不能加 NEXT_PUBLIC_，不能提交 Git 或发到聊天。先在供应商设置消费提醒/限制。资料会发送给供应商：仅使用公开活动文字，不包含账号信息、私信、个人身份资料。
4. 使用真实管理员联调：生成 → 保存 → 重复保存 → 编辑 → 提交 → 审核 → 公共可见；再用普通用户验证拒绝访问。当前云端没有 Supabase/AI 凭证，尚未执行这些真实托管链路，也没有产生 AI 调用费用。

生产启用、定时任务和来源采集需另行明确。后续可以接入经过许可的活动 Feed/API，固定来源定时整理为待审核草稿；不默认抓取任意网站。任何新增付费服务仍需运营者授权。

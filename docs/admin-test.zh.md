# 管理员审核联调

前置情况：两个普通账号的私有发布与图片隔离已经实测。当前尚无管理员测试凭据，不能把普通账号冒充管理员，也不能声称真实审核闭环已经通过。

## 准备专用网站管理员账号

如果已有专门用于测试的网站管理员，可以直接使用。否则：

1. 在网站注册第三个专用测试账号，并完成邮箱验证。保留之前两个账号为普通账号。
2. 在 Supabase → Authentication → Users 中找到新账号，复制它的完整 User UID。
3. 由项目所有者在 SQL Editor 中执行下面这段，将占位符替换为该专用账号的 UID：

   ```sql
   insert into public.user_roles(user_id, role)
   values ('替换成专用管理员测试账号的完整User-UID', 'admin')
   on conflict do nothing;
   ```

   该角色拥有网站后台权限，只授予确定的专用账号。不要在 user_metadata 中填写 admin 来代替数据库授权，也不要给之前的普通隔离测试账号增加管理员角色。

4. 在 Codex 当前环境设置中填写 `TEST_ADMIN_EMAIL` 和 `TEST_ADMIN_PASSWORD`，保存并发布环境。这里使用的是网站账号的登录信息，不是 Supabase 控制台或 Vercel 主账号。不要通过聊天发送密码，不需要提供 Service Role key。

## 测试范围

- 验证真实管理员可以读取概览，普通账号仍为 403。
- 由普通账号生成唯一标记的私有测试草稿并提交。
- 管理员只在唯一测试标记的搜索结果中操作该记录，明确选择“退回”，填写测试原因；不使用批量审核，不批准公开。
- 作者在“我的发布”展开退回原因，确认与管理员填写的一致；修改后重新提交。
- 验证状态与审计记录，再归档本轮记录。保留系统审计，不编辑其他用户信息。

批准公开、公开后下架与到期测试，需要另用所有者实际准备公开的真实内容。本轮不会为测试发布虚构活动、房源或招聘。

## 已补齐的反馈展示

个人中心在当前用户自己的每条被退回记录下提供“查看退回原因”。查询仅嵌入最新一条 rejected 审核记录，保留原有分页与计数，不加载完整审核历史。草稿、待审核、已归档等状态不展示历史退回说明。

反馈作为普通 React 文本渲染，不当作 HTML。缺失原因时显示清楚的提示。已有 RLS 的 owner/admin 限制继续生效，无需新增线上迁移。

隔离数据库测试覆盖作者读取最新原因、修改并重新提交，以及其他普通账号和匿名用户不能读取原因。真实管理员浏览器验证必须等专用账号配置完成。

## 测试完成后撤销专用账号的管理员角色（可选）

由所有者在 Supabase SQL Editor 中执行，仍只替换这个专用账号的 UID：

```sql
delete from public.user_roles
where user_id = '替换成专用管理员测试账号的完整User-UID'
  and role = 'admin';
```

本说明不会自动创建或撤销任何角色。不要删除用户账号、修改主账号权限或重跑既有迁移。
